# Catalogue des exigences fonctionnelles — Plateforme GET

Document produit pour l'Expression des Besoins métier. Les exigences ci-dessous sont **reconstruites** à partir du comportement réel du code (backend NestJS, frontend Next.js, schéma Prisma) tel que documenté dans les cinq inventaires techniques (`backend-inventory.md`, `frontend-inventory.md`, `data-model-inventory.md`, `roles-auth-inventory.md`, `docs-tests-inventory.md`), au 2026-08-05. Chaque exigence explique le **besoin métier** (le pourquoi) que le code observé satisfait, pas seulement le comportement technique. Rien n'est inventé : quand une exigence ne peut être confirmée avec certitude comme un besoin métier voulu (plutôt qu'un effet de bord du code), son statut est marqué `INFÉRÉE À CONFIRMER` et un commentaire explicite l'indique.

**Convention de statut** :
- `OBSERVÉE` : comportement vérifié dans le code (service/contrôleur) et généralement couvert par au moins un test automatisé.
- `PARTIELLEMENT OBSERVÉE` : comportement présent mais incomplet, incohérent, ou non testé.
- `DOCUMENTÉE NON OBSERVÉE` : décrite dans un document projet (ADR, audit) mais non retrouvée telle quelle dans le code actuel.
- `INFÉRÉE À CONFIRMER` : déduite de la structure du code (modèle de données, nommage) sans logique métier explicite retrouvée — nécessite confirmation du métier.
- `ABSENTE` : besoin identifiable mais aucune implémentation trouvée.
- `HORS PÉRIMÈTRE V1` : signalé comme non couvert intentionnellement à ce stade.

**Convention de priorité** : `Must` = fonction centrale du parcours (auth, candidature, paiement, admission) déjà observée ; `Should` = fonction de gestion/confort secondaire ; `Could` = extra (concours, partenaires financiers, CMS) ; `Won't` = hors périmètre explicite.

Numérotation strictement séquentielle sur l'ensemble du document : `GET-BES-FON-001` à `GET-BES-FON-138`.

## Synthèse

**138 exigences fonctionnelles** cataloguées (`GET-BES-FON-001` à `GET-BES-FON-138`), réparties sur 13 domaines : Authentification & compte (15), Profil étudiant (9), Catalogue écoles/offres (17), Candidature (13), Admission (6), Paiement (13), Inscription (9), Pédagogie/cours (15), Planification/emploi du temps (15), Messagerie (5), Notifications (8), Annonces (5), Ministère/conformité (8). Le domaine « Administration plateforme » n'a volontairement pas été isolé en 14ᵉ domaine distinct — voir note méthodologique ci-dessous.

**Note méthodologique sur le domaine « Administration plateforme »** : les fonctions propres à l'ADMIN_GET (gestion des utilisateurs, tableau de bord KPI, paramètres système, CMS landing, concours, partenaires financiers, audit, années académiques plateforme) sont **transverses** et ont été rattachées directement au domaine fonctionnel qu'elles administrent (ex. gestion des écoles → domaine Catalogue, gestion des candidatures → domaine Candidature) plutôt que regroupées artificiellement, à l'exception des fonctions strictement dédiées à la plateforme elle-même (utilisateurs, audit, paramètres système, CMS, concours, partenaires financiers) qui restent **à consolider dans un domaine « Administration plateforme » dédié lors d'une itération complémentaire** si le format de restitution l'exige — **point à confirmer avec le métier** sur le découpage attendu (organisation par acteur vs par fonction métier).

**Statuts observés** : la grande majorité des exigences (`OBSERVÉE`) sont corroborées par un test automatisé identifié dans `docs-tests-inventory.md`. Les exigences marquées `PARTIELLEMENT OBSERVÉE`, `ABSENTE` ou `INFÉRÉE À CONFIRMER` concentrent les principaux points de vigilance pour l'Expression des Besoins : préférences de notification non persistées (GET-BES-FON-120), canaux EMAIL/SMS/PUSH simulés (GET-BES-FON-118, 121, 122), jeton de reset non invalidé après usage (GET-BES-FON-011), statut `EXPIRED` du paiement non confirmé comme implémenté (GET-BES-FON-065), format réel du reçu de paiement à reconfirmer (GET-BES-FON-068), provisioning des comptes à rôle privilégié hors auto-inscription (GET-BES-FON-015), et portée exacte de l'ouverture de compte bancaire partenaire (GET-BES-FON-073).
